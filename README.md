## Про TCP
- **Сервер (Координатор)** - управляет турниром, хранит таблицу, принимает подключения игроков и наблюдателей.
- **Игрок (Студент)** - клиент, подключается по TCP, получает параметры, выбирает жест и отправляет его на сервер.
- **Наблюдатель** - клиент, подключается по TCP и получает поток событий турнира в реальном времени.
Взаимодействие - через TCP-сокеты. Сервер асинхронно обрабатывает несколько клиентов через select().

## Параметры запуска
### Сервер

```
./rsp server <port> <n> <seed> <strategy> <par> <delay> <tie_rule>
```

| Параметр | Значение                                                |
| -------- | ------------------------------------------------------- |
| port     | TCP-порт (например, 8080)                               |
| n        | число студентов (2…100)                                 |
| seed     | начальное значение ГСЧ                                  |
| strategy | 0 - случайно, 1 - по циклу, 2 - фиксированно            |
| par      | сколько партий идёт одновременно                        |
| delay    | пауза перед ходом, сек                                  |
| tie_rule | 0 - общее место при равных очках, 1 - строго по порядку |

### Игрок

```
./rsp player <ip> <port> <id>
```

### Наблюдатель

```
./rsp observer <ip> <port>
```

---
## Что гарантируется
1. Каждая пара играет ровно один раз.
2. Студент не играет две партии одновременно.
3. Жест фиксируется до раскрытия (сервер ждёт ходы от обоих игроков пары).
4. За победу - 2 очка, за ничью - 1, за поражение - 0.
5. Результат партии учитывается один раз.
6. Наблюдатели могут подключаться и отключаться в любой момент, не нарушая работу турнира.
---
## Завершение
- **Обычное:** после N(N−1)/2 партий печатается итоговый рейтинг, всем клиентам отправляется QUIT.
- По Ctrl+C на сервере: обработчик сигнала ставит флаг, сервер оповещает всех клиентов командой QUIT и корректно закрывает сокеты.
